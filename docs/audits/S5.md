### N2. The L1 <= L2 <= Linf check can be bypassed by "-" and "nan"

- Location: `makeTables`, the consistency check `awk` (about lines
  333-370).
- Evidence (scratch copies of the real sweep records, row
  `leftStructured/CC-2-EX_N32.row`):

  | Plant | rc | Result |
  | --- | --- | --- |
  | columns 5 and 6 swapped | 1 | caught: row N = 32, subset all |

  The check skips a triple that is all "-" for every row, including
  CCFV rows, where "-" is never valid. `/usr/bin/awk` (version 20200816)
  treats `"nan" + 0` as NaN, and every comparison with NaN is false.
  Allrun's checks (column count, convergence, the h column) make both
  cases unlikely in a real sweep, so the risk is low.
- Fix: require each value to match a numeric pattern. Allow "- - -" only
  in columns 17-22 of VCFV rows (nUnknowns = (N + 1)^2).

## Round 1 record

### Key finding: gradient consistency

Round 1 used scratch Python and `postProcess -func grad` on the tutorial
meshes, with "interior" meaning more than 2h from every boundary.
Maximum interior |grad(u) - (1, 2)|:

| N   | struct. Gauss | struct. LSQ | pert. Gauss | pert. LSQ |
| --- | ------------- | ----------- | ----------- | --------- |
| 16  | 1.6e-14       | 9.6e-15     | 0.720       | 1.0e-14   |
| 32  | 6.0e-14       | 2.4e-14     | 0.804       | 2.7e-14   |
| 64  | 1.2e-13       | 4.0e-14     | 0.948       | 7.1e-14   |
| 128 | 2.4e-13       | 1.0e-13     | 1.056       | 1.4e-13   |

The committed diagnostic, which uses a different interior definition,
agrees with these values.

Mechanism (v2412 source):

- `basicFvGeometryScheme.C`, lines 121-126: the weights place u_f where
  the segment P-N crosses the face plane, not at the face centroid. No
  skewness correction is applied.
- `gaussGrad` gives `grad = (1/V) sum Sf u_f`.
- On a skewed triangle, u_f has an O(h) error for a linear field. Each
  face then contributes O(h^2), and dividing by V = O(h^2) gives an
  O(1) gradient error.
- On the structured Left meshes the P-N segments cross the faces at
  their centroids.
- `linearUpwind` therefore has O(h) face errors, so CC-2 and CC-2-EX are
  first order on perturbed meshes. CC-2-LS changes only the gradient
  and recovers L1 order 2.
- Possible remedies (the developer's choice): `skewCorrected linear` or
  `leastSquares`.
