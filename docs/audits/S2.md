## Numerics review

All of these were checked against `CLAUDE.md` section 7 and my own
derivations.

- **Velocity and flux signs.**
  - A = `vector(a, 1, 0)` comes from `a` alone.
  - phi = A . S_f, with S_f outward from the owner.
  - Measured patch fluxes: `tStart` and `xLeft` -h (inflow); `tEnd`
    and `xRight` +h (outflow).
  - With a = 0.5 only the x patches change (∓h/2).
  - Upwinding in t takes the earlier cell, which is backward Euler.
- **Boundary values.**
  - The analytical value is evaluated at `patch().Cf()`, both in the
    dictionary constructor and in `updateCoeffs()`.
  - The boundary condition uses the registered `spaceTimeProperties`
    when one exists, and reads the file otherwise.
- **Convergence test.**
  - The test uses the normalised initial residual of the upwind matrix
    with the linearUpwind correction evaluated at u^n. That equals the
    full discrete residual at u^n.
  - My own scratch evaluation of `fvc::div(phiST, u)` with the case
    scheme, at the written u, gives a largest cell imbalance of:

    | Case | max cell imbalance |
    | --- | --- |
    | CC-1, Right, N = 8 | 0 |
    | CC-2, Right, N = 64 | 6.0e-13 |
    | CC-2-LS, Right, N = 64 | 3.1e-11 |
    | CC-2, Left, N = 128 | 9.1e-13 |

    Typical |phi| is 0.01 to 0.08, so the equations are satisfied at
    convergence.
- **Error norms.**
  - e = u_P - u_exact(centroid), weighted by V/Lz.
  - L1 and L2 are normalised within each subset, and L-infinity is a
    plain max.
  - Boundary cells are those with a face on a patch that is neither
    empty nor coupled.
  - At t = T, weights are the face lengths, with the extrapolated value
    u_P + grad(u)_P . (x_f - x_P) and the cell value u_P.
- **Mesh size and orders.**
  - h = sqrt(A_front/(nTri/2)) = 1/N.
  - p = log(e_c/e_f)/log(h_c/h_f). Hand check: log(0.08527034/
    0.04190567)/log 2 = 1.025, as stored.

## Backward-Euler test

- **Argument.** Summing A . S_f u_f over a quad cell gives
  dx (u_{i,m} - u_{i,m-1}) + a dt (u_{i,m} - u_{i-1,m}) = 0, which is
  backward Euler with upwinding in space. This is correct.
- **Inflow shift.**
  - The `xLeft` face centres lie at t_{n+1/2}, so the 1D inlet uses
    u(0, t - dt/2).
  - The v2412 `Sine` Function1 (`SineI.H`) is
    amplitude sin(2 pi f (t - t0)) scale + level, so amplitude -1 with
    t0 = 0.05 is right.
- **Pairing.**
  - Each space-time cell is matched to the 1D cell with the same x to
    1e-12 at time m dt.
  - The cell, row and time counts and the unpaired and duplicate counts
    are all checked.
  - Both cases write with precision 17, so the 1e-10 threshold is
    meaningful.
- **Rerun:** 1.221245e-15, PASS.
- **Planted faults** in scratch copies:
  - t0 = 0 gives 2.70e-01, FAIL, exit 1;
  - `linearUpwind` in the space-time case gives 7.69e-01, FAIL, exit 1.

  The max |u| > 0.5 guard also rules out a trivial solution.

## Independent assessment of the benchmark findings

### Finding 1: characteristic alignment on Right (confirmed)

- On Right meshes with a = 1, all N^2 diagonal faces have phi exactly 0.
  Every cell has 1 inflow face, 1 outflow face and 1 zero-flux face
  (128 of 128 cells at N = 8, 8192 of 8192 at N = 64).
- CC-1 then gives u_P = u_in: 2 iterations, imbalance exactly 0, and the
  same L-infinity in every subset.
- The t = T cell value is exact (about 1e-16), because the `tEnd` and
  inflow face centres of each diagonal strip lie on the same
  characteristic.
- With `Left` the errors are much larger: at N = 64, CC-2 L1_all is 5.1
  times larger and CC-1 L1_all 11 times larger.
- **Decision:** Left is used for the benchmark and Right only as an
  illustration.

### Finding 2: L-infinity and the outflow strip (confirmed)

- In v2412, `linearUpwind::correction` fills internal faces and, among
  the patches, only `coupled()` ones. With zeroGradient, u_f = u_P, and
  an outflow boundary cell gets u_P = u_in, which is O(h) away from the
  value at its centroid.
- The maximum error always lies in a cell touching `tEnd` or `xRight`,
  on both diagonal families.
- A strip of O(h) errors gives L1 ~ h^2, L2 ~ h^1.5 and Linf ~ h:
  - on Right, CC-2 L2_all is 1.61, 1.55, 1.53 and then 1.51 (N = 128);
  - on Left, 128 to 256 gives L1_all 2.07, L2_all 1.51 and Linf_all
    0.99 (audit scratch run at N = 256).
- **Decision:** keep zeroGradient as the primary outflow; add
  `spaceTimeLinearExtrapolation` before S5; report the strip signature
  in the guide.

### Finding 3: interior L-infinity contamination (confirmed; extended)

- **Gauss linear.**
  - The interior maximum is always in a cell next to an outflow
    boundary cell. On Left at N = 128 and 256 it is next to the
    top-right corner.
  - The contamination does not stay in one layer:

    | N | Linf, three layers excluded |
    | --- | --- |
    | 64 | 5.32e-3 |
    | 128 | 2.73e-3 |
    | 256 | 1.40e-3 |

    That is order 0.96 in both steps.
  - The interior Linf order is 0.907 (64 to 128), then 0.978 (128 to
    256). This supports the builder's outflow-leakage explanation.
- **leastSquares** (added by this audit).
  - v2412 `fvPatch::delta()` returns only the patch-normal part,
    nHat (nHat . (Cf - Cn)), and `leastSquaresVectors` uses it on
    non-coupled patches.
  - The centroid of these triangles is offset tangentially by h/6 from
    the boundary face centre, so the LS gradient has an O(1) error in
    the boundary cells.
  - On Right meshes, the inflow-only boundary cells of CC-2-LS are first
    order (Linf 0.0217, 0.0109, 0.0054 for N = 16, 32, 64), with the
    maximum at `xLeft`, t ≈ 0.53, far from any outflow.
- **Decision:** both effects are recorded in `CLAUDE.md` section 7 and
  must be reported in the guide.

### Re-audit: t = T L-infinity equal to sin(pi h) on Left (confirmed)

The Left mesh, A = (1, 1) and the data are all symmetric under the swap
x ↔ t:

- tStart ↔ xLeft and tEnd ↔ xRight;
- the diagonals keep direction (1, -1);
- the solution u = sin(2 pi (x - t)) is odd under the swap.

The discrete solution should therefore satisfy u(t, x) = -u(x, t). The
audit checked this on the written fields:

- max |u(x, t) + u(t, x)| over all mirrored cell pairs is 3.9e-15
  (CC-2, N = 16), 3.3e-15 (CC-2, N = 128) and 4.6e-15 (CC-2-LS,
  N = 128);
- the top-right corner cell lies on the line x = t, so its value is 0
  to round-off (1.6e-16 at N = 128).

That corner cell has two zeroGradient outflow faces. Its `tEnd` face
centre (1 - h/2, 1) has exact value -sin(pi h), so the t = T cell error
there is exactly sin(pi h): 0.195090, 0.098017, 0.049068 and 0.024541
for N = 16 to 128, matching sin(pi/N).

The explanation is correct. It also shows that the t = T L-infinity on
Left is purely an outflow-corner quantity:

- it is identical for CC-2 and CC-2-LS;
- it is first order;
- it is not a measure of interior accuracy.

At N = 8 the maximum is elsewhere (0.695, while sin(pi/8) = 0.383).
The t = T L1 of the cell value is second order (2.18, 2.10, 2.08).

### Re-audit: CC-1 pre-asymptotic behaviour (plausible, trends to 1)

- The CC-1 L1_all orders on Left are 0.466, 0.645, 0.780 and 0.871
  (N = 8 to 128). An audit run at N = 256 gives 0.925 (L2 0.919, Linf
  0.897).
- The CC-1 Linf error at N = 8 is 0.96, almost the full amplitude.
- Coarse-mesh upwind dissipation damps the k = 1 wave by an O(1)
  factor, so the error saturates and the observed order falls below 1.
  As h decreases the damping becomes linear in h, and the order climbs
  steadily towards 1.
- This is plausible, and the trend is monotone and continues at
  N = 256.

### Re-audit: iteration growth (no sign of a problem)

- every run converges to below 1e-10;

- the growth in outer iterations (84 at N = 256) comes from a slowly
