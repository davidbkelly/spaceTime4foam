# Audit S3: VCFV geometry

Auditor: foam-auditor. Branch `step-one`, commits `292486d..08937b6`
(9 commits, not pushed). OpenFOAM.com v2412 on macOS (clang 17).

## Summary

The median-dual geometry is correct. I built my own dual cells from the
edge midpoints and triangle centroids, directly from the `polyMesh`
files and not through the library. On Left N = 2, perturbed Left N = 8
and perturbed Right N = 3, the library's V_j, n_jk and n_B agree with it
to 2e-16 at every node and edge, corners included. The unweighted LSQ
gradient matches my own LSQ on nonlinear data to 5e-15. A clean rebuild
has 0 compiler warnings. `./Alltest` passes 8 of 8 tests. shellcheck
(32 scripts) and markdownlint are clean. Rerunning the tests reproduces
the identity table and the checksums bit for bit.

I planted 15 faults. The tests catch 13 of them. Two slip through
(Should fix 1 and 2):

- an LSQ that is consistently distance-weighted;
- a perturbation with dt = dx.

Neither is Blocking.

**Verdict: PASS** (0 Blocking, 2 Should fix, 7 Minor).

## Geometry against the paper and CLAUDE.md

- Paper (Tufillaro et al.):
  - Eq. 18 gives the interior coefficient 2/(d(d+1)), which is 1/3 for
    d = 2.
  - Remark 1 (Eq. 81) is the boundary correction. Its 2D analogue is
    (1/3)(1/2) n_B = n_B/6.
  - Remark 3 gives the closure weight: 1/4 in 4D, so 1/d = 1/2 in 2D.
  - Eq. 20 has the factor 1/(2d) = 1/4.
  - The code matches all four: `medianDualMesh.C:500-518` for the
    geometry, `Test-medianDualMesh.C:337-351` for the closure and the
    V identity.
- My derivation of the boundary coefficient: in triangle T, the true
  dual-face vector from j to k is (n_j^T - n_k^T)/6. Since
  n_j^T + n_k^T + n_l^T = 0, this equals n_j^T/3 + n_l^T/6, where
  n_l^T is the normal of edge jk pointing away from l.
  - On an interior edge the two n_l^T terms cancel.
  - On a boundary edge the n_l^T term is n_B. So n_jk plus n_B/6 is the
    exact dual face.
- **V identity at boundary nodes is valid.** Take a dual face from the
  midpoint m_jk to the centroid c, with normal n. The quantity
  (x - p_j) . n is constant along it and equals
  0.5 (p_k - p_j) . n_face.
  - On the half boundary edges at j, (x - p_j) . n_B = 0, because x
    lies on the line through p_j.
  - The divergence theorem, V_j = 0.5 * (integral of (x - p_j) . n),
    then gives V_j = 0.25 sum_k (p_k - p_j) . n_jk.
  - This holds at every node, provided n_jk includes the n_B/6 term.
    The builder's claim is correct.
- Orientation:
  - `normalAwayFrom` (`medianDualMesh.C:96-115`) sets every sign by a
    dot-product test.
  - Edges are stored as (min, max) (line 252).
  - The front triangles from gmshToFoam all have negative signed area
    (for example 128 of 128 at P8), so nothing depends on the winding.
- Independent check, library against my own construction (`indep.py`):

```text
L2 nodes 9  edges 16  maxdiff V 3.5e-17 n_jk 1.2e-16 n_B 0 j>=k 0
P8 nodes 81 edges 208 maxdiff V 1.2e-16 n_jk 1.8e-16 n_B 0 j>=k 0
R3 nodes 16 edges 33  maxdiff V 4.9e-17 n_jk 1.2e-16 n_B 0 j>=k 0
L2 corner (0,0): V = 1/24, n(0,0)->(0,.5) = (1/12, 1/6)  [hand: same]
L2 interior (.5,.5): V = 1/4, six edges match
```

- Right triangle:
  - V = 1/6 at all three nodes.
  - The edge vectors are (1/3, 1/6), (1/6, 1/3) and (-1/6, 1/6).
  - The edge (1, 0) to (0, 1) is stored from the node (0, 1), so the
    test's flip branch runs.

## LSQ

- The implementation (`medianDualMesh.C:523-571`):
  - M_j is summed over all edges at j, zz = 1, and the matrix is
    inverted with `inv()`.
  - A node is rejected as singular if det2D <= 1e-12 * scale^2.
  - The coefficients are precomputed.
  - `gradient()` is a single loop over the edges, with the correct sign
    for node k.
- The singularity guard works. With the boundary edges dropped from M
  (fault g), the corner node stops with "least-squares matrix ...
  singular".
- The test data u = 0.3 + 1.7x - 2.3t are genuinely linear, with a
  nontrivial c. The test checks every node and reports interior,
  boundary and corner nodes separately. The largest absolute error is
  1.6e-14 (the builder claimed < 1.7e-14).
- On nonlinear data u = sin(7x + 3t^2), the library matches my own
  unweighted LSQ to 5.3e-15 (P8).

## Perturbation

- The distribution is correct. `rnd.position<scalar>(-m, m)` is
  -m + U(2m), a uniform deviate. dx is drawn and then dt, for interior
  nodes only (`perturbSpaceTimeMesh.C:170-190`).
- Boundary nodes are the endpoints of every boundary edge, so corners
  are included. In the test all 256 boundary points are unchanged, bit
  for bit.
- The back point gets the same displacement.
- The area check and `-maxFraction 0.6` work (fault k).
- The log shows the seed and maxFraction.
- The checksums are compared within one run only (see Minor 3).
- Measured: max |dx| = 0.199904 h and max |dt| = 0.199972 h. The same
  seed gives the same checksum (dbf9a8c9...), and seed 7 a different
  one. CC-2 on perturbed N = 32 converges in 39 iterations.
- **`Random` portability** (v2412 `Random.H:68-71`, `Random.C:115`):
  - The generator is OpenFOAM's own `Rand48`, which is portable.
  - `scalar01()` goes through `std::uniform_real_distribution<double>`.
    Its algorithm is implementation-defined. libc++ and libstdc++
    currently both use two 31-bit draws in `generate_canonical` with the
    same arithmetic, so the meshes probably agree, but nothing
    guarantees it.
  - See Minor 3 for the recommendation.

## Should fix

1. **A weighted LSQ passes every test.**
   - Where: `Test-medianDualMesh.C:595-680`.
   - Evidence: fault h (M and the coefficients both weighted by
     1/|d|^2) passes RT and ID. Linear exactness holds for any
     consistent weighting, so the tests cannot detect this departure
     from the unweighted LSQ in CLAUDE.md section 7.
   - Fix: add a nonlinear check (for example u = x^2 + x t) against an
     unweighted LSQ recomputed in the test from the neighbour lists.
     Run it on the ID meshes. The right triangle cannot tell the
     weightings apart: each node there has only two neighbours, so any
     weighting gives the same interpolating gradient.
2. **Correlated dx and dt pass the perturbation test.**
   - Where: `tests/perturbSpaceTimeMesh/Allrun:190-215`.
   - Evidence: fault l (dt = dx) passes PT and ID. The bounds checks
     test only max |dx| and max |dt|.
   - Fix: in `compare`, count the interior points with dx == dt (it
     should be about 0). A stronger fix is to check the sample
     correlation, or to compare with stored reference displacements
     (see Minor 3).

## Minor

1. **The guard rejects some Gauss-type schemes.**
   - Where: `spaceTimeLinearExtrapolationFvPatchScalarField.C:36-73`,
     and the class description in the `.H`.
   - Evidence: `cellLimited<cubic> 1.5 Gauss linear 1` is valid in
     v2412, because `cubic(Istream&)` reads `rt_`. The guard treats it
     as not Gauss-type and stops, since the second token is 1.5. The
     header says that `cellLimited<limiter>` followed by Gauss is
     allowed.
   - This is safe (fatal, not silent).
   - Fix: skip a number token after `cellLimited<...>`, or document the
     limitation.
2. **The guard test does not cover every scheme on the allow-list.**
   - It does not run `iterativeGauss`, `pointCellsLeastSquares` or the
     MD/face-limited forms. I checked them by hand (above), but the
     test does not keep them checked.
   - Fix: add two entries to `guardSchemes`.
3. **Random portability.**
   - The meshes are reproducible on one platform. Across libc++ and
     libstdc++ this is likely but not guaranteed (see Perturbation).
   - Fix: store a reference (the seed-12345 checksum at N = 8, or a few
     displacements to 1e-15) in the test, so any drift is caught rather
     than changing the benchmark meshes silently.
   - Optionally, draw from `Foam::Rand48` directly (public class,
     `Rand48.H`): u = gen()/2^31 is fully portable, with a 31-bit
     resolution.
4. **S2b Minor 3 is still open.**
   - Where: `spaceTimeLinearExtrapolationFvPatchScalarField.H:78`.
   - The header still says "cells downstream of" the corner.
   - Fix: say "cells near it".
5. **The summary table of `medianDualIdentities` omits a column.**
   - Its "V identity" column shows interior nodes only. Boundary nodes
     are checked, but the table does not show them.
   - Fix: add a column.
6. **The LSQ tolerance is loose.**
   - The scale |c| + max|u|/(shortest edge) is at least 67 at N = 32
     (max|u| = 2), so the absolute tolerance is at least 1.5e-11,
     against errors of 1e-14.
   - It still caught fault f (0.034), but it could hide a small defect.
   - Fix: use the scale |c|.
7. **The foam-extend branch is untested.**
   - `Test-medianDualMesh` uses unguarded OpenFOAM.com API:
     `getOrDefault`, `cfind().good()` and `val()`.
   - This is consistent with the open S2 Minor. Leave it untested and
     undeclared.
