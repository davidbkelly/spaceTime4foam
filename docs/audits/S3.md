## Geometry against the paper and CLAUDE.md

- Paper (Tufillaro et al.):
  - Eq. 18: the interior coefficient 2/(d(d+1)) is 1/3 for d = 2.
  - Remark 1, Eq. 81: its 2D form is (1/3)(1/2) n_B = n_B/6.
  - Remark 3: the closure weight 1/d is 1/2.
  - Eq. 20: the factor 1/(2d) is 1/4.
  - The code matches all four: `medianDualMesh.C:500-518`, and
    `Test-medianDualMesh.C:337-351`.
- Derivation of the boundary coefficient:
  - In triangle T, the true dual-face vector from j to k is
    (n_j^T - n_k^T)/6.
  - With n_j^T + n_k^T + n_l^T = 0, it equals n_j^T/3 + n_l^T/6.
  - The n_l^T terms cancel on interior edges. On boundary edges,
    n_l^T = n_B.
  - So adding n_B/6 gives the exact dual face.
- **The V identity holds at boundary nodes.**
  - Along a dual face from m_jk to c, (x - p_j) . n is constant, and
    equals 0.5 (p_k - p_j) . n_face.
  - Along the half boundary edges at j it is zero.
  - The divergence theorem then gives
    V_j = 0.25 sum_k (p_k - p_j) . n_jk at every node, provided n_jk
    includes n_B/6.
- **Orientation:**
  - `normalAwayFrom` (`medianDualMesh.C:96-115`) sets every sign with a
    dot-product test.
  - Edges are stored as (min, max) (line 252).
  - Every front triangle from gmshToFoam has negative signed area
    (for example 396 of 396 on the unstructured mesh), so nothing
    depends on the winding.
- **Independent check** (C++, `auditS3/indep/indepDual.C`). It builds
  its own dual cells and its own LSQ from the raw faces, with the
  neighbours taken from the triangles, not from the library's edges:


## LSQ

- M_j is summed over all the edges at j, with zz = 1, and inverted with
  `inv()`. The singularity guard is det2D <= 1e-12 scale^2.
- The coefficients are precomputed. `gradient()` is a single edge loop,
  with the correct sign for node k.
- **New check 9b** (`Test-medianDualMesh.C`, commit `73022a1`):
  - u = sin(3x) cos(2t) + x^2 t, compared with an unweighted LSQ that
    the test solves itself by Cramer's rule.
  - That LSQ is independent of the precomputed coefficients. It uses
    only the node points, the u values and the edge list (whose
    topology checks 5 and 8 verify separately).
  - Tolerance: 1e3 eps relative to the largest edge slope at the node.
    The largest value observed is 1.1e-15, a margin of about 200.
- **Linear check 9:**
  - The tolerance is now absolute: 1e3 eps |c|, about 6.4e-13.
  - The largest error observed is 1.6e-14 (perturbed N = 32).
  - See new Minor B.
- The table in `medianDualIdentities` now shows "V bnd", "LSQ lin" and
  "LSQ nonl" (commit `ad01997`).

## Unstructured mesh

- It is built by gmsh algorithm 6 (Frontal-Delaunay) with one thread
  and a fixed seed. Three gmsh runs gave identical MSH files
  (md5 6d604967...).
- It has 396 triangles and 225 nodes. The interior valences are
  5: 22, 6: 133 and 7: 18.
- It has the same five patch names, with 13 boundary edges on each
  side, and it passes every identity check.

## Perturbation

- The distribution: `Random::position<scalar>(-m, m)` is
  -m + U(0,1) 2m (`Random.C:115`). It is uniform and drawn separately
  for each component, dx before dt, for interior nodes only.
- Boundary nodes are all the endpoints of boundary edges, so corners
  are included. All 256 boundary points are unchanged, bit for bit.
- The back partner gets the identical displacement.
- The area check makes `-maxFraction 0.6` fatal.
- The log states the seed and maxFraction.
- **New independence check** (commit `5487739`):
  - Fewer than 1% of the 961 interior points may have dx = +/-dt,
    to 1e-9 h.
  - The sample correlation of dx and dt must satisfy |r| < 0.1.
  - Observed: 0 such points, r = 0.0133.
  - The threshold is stated: 0.1 is about 3.1 standard errors
    (1/sqrt(961) = 0.032).
  - The seed is fixed, so the check is deterministic and not flaky.
- **New stored references** (Left N = 8, seed 12345):
  - They are the first five (point, dx, dt) values and the SHA-1 of the
    points file.
  - Both are compared exactly, as whole strings.
  - I checked the stored values against a separate C++ program
    (`auditS3/rnd/rnd.C`). It calls `Random(12345)` directly with
    m = 0.2/8. Its first five (dx, dt) pairs match the stored values
    to 3e-17. That difference is expected: the stored values are
    differences of the written coordinates.
  - The checksum 58859dc6... reproduces.
- **`Random` portability** (Minor 3):
  - `Rand48` is OpenFOAM's own generator and is portable.
  - `std::uniform_real_distribution` is implementation-defined.
  - This is now stated in the `perturbSpaceTimeMesh` header and next
    to the stored values. The developer's decision is still pending.
- Reruns reproduce every number: the checksums dbf9a8c9... (seed 12345,
  N = 32) and e2296c26... (seed 7), max |dx| = 0.199904 h,
  max |dt| = 0.199972 h, and CC-2 converging in 39 iterations.

## Minor

1. **New: the checksum also covers the file header.**
   - Where: `tests/perturbSpaceTimeMesh/Allrun`, stored references.
   - Evidence: the SHA-1 is taken over the whole points file. That
     includes the banner (`Version: 2412`) and the `arch` entry. An
     OpenFOAM upgrade would change the checksum even with identical
     points, and the comment names only the toolchain and gmsh. The
     stored displacements are the robust check.
   - Fix: say so in the comment, or checksum only the point list, for
     example the lines after the opening `(`.
2. **New: the linear LSQ tolerance is fixed while the error grows with N.**
   - Where: `Test-medianDualMesh.C`, check 9.
   - Evidence: the tolerance is 6.4e-13. The error scales as
     eps max|u|/h: 1.6e-14 at N = 32, so about 1.3e-13 at N = 256.
     That is fine for the N of 32 or less used in the test. It would
     approach the tolerance only on very fine meshes.
   - Fix: none needed now. If the test is later run at larger N, scale
     the tolerance by 1/h.
3. **(first-audit Minor 3) `Random` portability**: documented; the developer's
   decision is pending.
4. **(first-audit Minor 7) foam-extend branch untested**: accepted.
